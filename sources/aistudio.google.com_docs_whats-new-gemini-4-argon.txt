https://aistudio.google.com/docs/coding-agents.md What's new in Gemini 4 Argon Gemini 4 Argon
(gemini-4-argon) is our efficient Gemini 4 frontier reasoning model.
It delivers Gemini 4 intelligence with faster responses and lower token spend per turn compared to
[Gemini 4 Carbon](/docs/whats-new-gemini-4-carbon) across complex coding, agentic, math, and science
tasks.
Gemini 4 Argon is available through the Gemini API and in Google AI Studio.
Gemini 4 Argon supports a unified 1M-token context window, long decode up to 1M tokens, and tunable
thinking levels (low, medium, high).

Choosing between Carbon, Argon, and other models {% id="choosing-between-models" %} Gemini 4 Argon
and [Gemini 4 Carbon](/docs/whats-new-gemini-4-carbon) share the same 1M unified context window,
built-in tools, and per-token pricing.
The main difference is how many thinking tokens each model spends per turn: Gemini 4 Carbon
(gemini-4-carbon): Built for tasks that push the limits of reasoning depth.
Carbon spends more thinking tokens per turn to explore thoroughly and verify its work, which
increases per-turn token use and latency compared to Argon.
Use it for complex root-cause debugging, architectural design, dense multimodal synthesis,
scientific proofs, and security auditing.
Gemini 4 Argon (gemini-4-argon): Our efficient Gemini 4 frontier reasoning model, ideal for most
advanced software engineering and knowledge work tasks.
It delivers Gemini 4 intelligence with faster responses and lower token spend per turn compared to
Carbon on interactive coding, day-to-day feature work, and fast production loops.
For more guidance on model selection, see [Latest Gemini models](/docs/latest-modelcompare-models).
Understanding thinking levels {% id="understanding-thinking-levels" %} The [thinking
level](/docs/thinking) is your main control over quality, latency, and token use in Gemini 4 Argon:
| Thinking level | Token use | When to use | | :--- | :--- | :--- | | low | Fewest tokens, lowest
latency | Simpler tasks and cost-sensitive work.
Also works for analysis and writing tasks that need light thinking.
Quality can drop on hard tasks.
| | medium (default) | Balanced | Recommended for most tasks, including complex code and agentic use
cases.
| | high | Most tokens, slowest first token | Complex reasoning, hard math and science, and the most
difficult code or agent tasks.
Pairs well with long decode for long outputs.
| Run your evaluations at all three levels, then pick the lowest level that meets your quality bar.
To learn more, see the [thinking guide](/docs/thinking).

%} Larger output and long decode {% id="long-decode" %} Gemini 4 Argon can think longer on hard
math, science, and coding problems.
Use thinkinglevel to control reasoning depth: thinkinglevel sets how deeply the model reasons before
answering.
maxoutputtokens caps your combined thinking and output tokens.
The response stops once thinking plus output hits maxoutputtokens, so set it high enough to leave
room for the final answer.
Generate past 64K tokens with background execution: Standard synchronous responses stop at 65,536
tokens.
To generate longer responses, set background=True and raise maxoutputtokens above 65,536 (up to the
unified 1M-token context window, minus your input tokens).
Our servers generate the response in 64K-token continuation hops for you.
Each hop adds a modeloutput step to interaction.steps, so join the text across all modeloutput steps
when the interaction finishes.
{% tabs %} {% tab label="Python" %} python import time from google import genai client =
genai.Client() interaction = client.interactions.create( model="gemini-4-argon", input="Write a
complete, rigorous proof of the prime number theorem.", background=True, generationconfig={
"maxoutputtokens": 262144, "thinkinglevel": "high", }, ) while interaction.status in ("inprogress",
"queued"): time.sleep(5) interaction = client.interactions.get(id=interaction.id) Each hop adds a
modeloutput step, so join the text of all of them.
text = "".join( content.text for step in interaction.steps if step.type == "modeloutput" for content
in step.content if content.type == "text" ) print(text) print("Status:", interaction.status)
print("Usage:", interaction.usage) {% /tab %} {% tab label="JavaScript" %} javascript import {
GoogleGenAI } from "@google/genai"; const client = new GoogleGenAI({}); let interaction = await
client.interactions.create({ model: "gemini-4-argon", input: "Write a complete, rigorous proof of
the prime number theorem.", background: true, generationconfig: { maxoutputtokens: 262144,
thinkinglevel: "high", }, }); while (interaction.status === "inprogress" || interaction.status ===
"queued") { await new Promise((resolve) = setTimeout(resolve, 5000)); interaction = await
client.interactions.get(interaction.id); } // Each hop adds a modeloutput step, so join the text of
all of them.
const text = interaction.steps .filter((step) = step.type === "modeloutput") .flatMap((step) =
step.content ??
[]) .filter((content) = content.type === "text") .map((content) = content.text) .join("");
console.log(text); console.log("Status:", interaction.status); console.log("Usage:",
interaction.usage); {% /tab %} {% tab label="REST" %} bash ID=$(curl -s -X POST

callout type="note" %} If you set background: true without defining maxoutputtokens, the server
stops after 64K tokens.
{% /callout %} Background execution is the recommended way to run long decode.
It runs the continuation loop server-side until the model finishes or reaches maxoutputtokens.
If you need finer-grained control over retries, backoff, and error handling (or don't want your
interactions stored), you can use client-side continuation in the [Interactions

For streaming, reconnection, token counting, and when to use long decode, see the [long decode
guide](/docs/long-decode).
Setting output token limits {% id="setting-output-token-limits" %} maxoutputtokens sets the maximum
combined thinking and output tokens for a response.
Set it high enough that thinking doesn't cut the answer short, and low enough to limit spend when a
hard prompt uses all of it.
Use these values as a starting point: Standard tasks: Keep the default of 65,536 or don't set any
value.
Existing apps with a limit lower than 32K: Raise maxoutputtokens to at least 32,768.
Gemini 4 Argon can spend more of the limit on thinking than earlier models.
To use fewer tokens, lower the thinking level instead.
Complex reasoning and coding: Set background: true and set maxoutputtokens to 131,072 or 262,144, up
to 1,048,576 minus your input tokens.

Migration checklist {% id="migration-checklist" %} {% callout type="note" %} Automate this migration
with a coding agent.
If you use a coding agent that supports skills (like Antigravity), install the [gemini-api-dev
skill](/docs/coding-agentsgemini-api-dev) and run: none /gemini-api-dev migrate my app to Gemini 4
Argon {% /callout %} Migrate to gemini-4-argon {% id="migrate-to-gemini-4-argon" %} Update model ID:
Change your target model string to gemini-4-argon.
Review maxoutputtokens: If you set it explicitly today, consider raising it.
We recommend at least 32,768, since Gemini 4 Argon can spend more of the limit on thinking.
Configure thinking level: Choose low, medium (default), or high, and test your workload at all
three.
Move off explicit context caching: Explicit caching (cachedContents / caches.create) is not
supported on Gemini 4 Argon.
Remove calls that create or reference cachedcontent from your requests.
[Implicit caching](/docs/caching) is enabled by default for prompts of at least 4,096 tokens and
discounts cached input tokens by 95% on cache hits.
Remove sampling parameters: Remove temperature, topp, and topk from your requests.
If provided, they are ignored.
Use background execution for long outputs: For tasks that need more than 64K tokens, set background
to true and maxoutputtokens greater than 65,536.
Increase client timeouts: Hard prompts can take several minutes.
Use background execution, or set HTTP client timeouts to at least 15 minutes.
Keep conversation state on the server: Use previousinteractionid for multi-turn and function calling
conversations.
Review your cost estimates: Every token the model processes is billed, including internal tool
system instructions and function declarations when using grounding (see
[Pricing](/docs/whats-new-gemini-4-argonpricing)).
Pricing {% id="pricing" %} Gemini 4 Argon is available at introductory pricing through November 30,
2026: Input tokens: $2.00 per 1M tokens ($4.00 starting December 1, 2026) Cached input tokens:
Implicit caching discounts cached input by 95%, to $0.10 per 1M tokens ($0.20 starting December 1,
2026).
Output tokens, including thinking tokens: $10.00 per 1M tokens ($20.00 starting December 1, 2026)
Every token the model processes is counted and billed, including thinking tokens and internal tool
system instructions and function declarations when using grounding.
Grounding with Google Search also remains billed per query.
Gemini 4 Argon is not available on the Free tier.
