The following sections cover moving to Claude Fable 5.2, or to Claude Mythos 5.2, from Claude Fable
5.1, Claude Mythos 5.1, Claude Opus 5.5, or an earlier Claude Fable, Claude Mythos, or Claude Opus
model.
For the changes themselves, see What's new in Claude Fable 5.2 .
For behavioral differences and model-specific prompting patterns, see Prompting Claude Fable 5.2 .
Claude Fable 5.2 is available on the Claude API, Amazon Bedrock ( bedrock-runtime ) , Claude
Platform on AWS , Claude Models on Google Cloud (Anthropic managed) , Claude Models on Google Cloud
(Google managed) , and Microsoft Foundry .
Claude Mythos 5.2 has the same capabilities and is available only to organizations verified through
Anthropic's verification programs, such as the Cyber Verification Program .
The baseline settings shared by claude-fable-5-2 and claude-mythos-5-2 : Thinking: Adaptive thinking
is always on, unchanged from Claude Fable 5.1.
The model determines when and how much to think, and the effort parameter controls how deeply.
Both thinking: {type: "disabled"} and manual extended thinking ( thinking: {type: "enabled",
budgettokens: N} ) return a 400 error.
Effort: All five effort levels are supported, and the default is high , unchanged from Claude Fable
5.1.
See Recommended effort levels for Claude Fable 5.2 .
Prefill: Prefilling the assistant message returns a 400 error, unchanged from Claude Fable 5.1.
Use system prompt instructions instead.
Sampling parameters: Omit temperature , topp , and topk , as on Claude Fable 5.1.
See Sampling parameters for the values that return a 400 error.
Tool choice: {type: "auto"} (the default) and {type: "none"} are supported.
Forcing a tool call with {type: "any"} or {type: "tool", name: "..."} returns a 400 error, unchanged
from Claude Fable 5.1.
Structured outputs: In an organization with customer-managed encryption keys (CMEK), structured
outputs aren't available for either model, as for Claude Fable 5.1.
That covers both strict tool use and JSON outputs.
If your requests set strict: true or outputconfig.format there, remove them and validate the output
in your code.
Preserved thinking across models: On the Claude API and Claude Models on Google Cloud (Google
managed), Claude Fable 5.2 and Claude Mythos 5.2 read each other's thinking blocks and those from
other models, including Claude Opus 5.5, Claude Sonnet 5.5, and Claude Haiku 5.5.
No other model reads their blocks.
See Which model switches keep the reasoning on the Claude API for the list.
Account-bound thinking: Thinking blocks from Claude Fable 5.2 and Claude Mythos 5.2 work only in the
account that produced them, or in an account linked to it.
When another account sends one of these blocks, the API drops the block before the model receives
it, and the request succeeds.
On the Claude API and Claude Models on Google Cloud (Google managed), with the
thinking-binding-controls-2026-08-01 beta header, the response lists each dropped block in
inputtransformations with reason: "organizationbindingmismatch" .
See Accounts and cloud platforms .
Context window and output: A 1M token context window by default, and up to 128k output tokens for
each request.
Pricing: $8 USD per million input tokens and $40 USD per million output tokens, compared with $10
USD and $50 USD on Claude Fable 5.1 and Claude Mythos 5.1.
Prompt cache reads are $0.20 USD per million tokens, compared with $0.25 USD on those models.
See Pricing .
Data retention: Both models require 30-day data retention, aren't available under zero data
retention (ZDR) arrangements unless expressly authorized by Anthropic, and are designated Covered
Models, the same as Claude Fable 5.1 and Claude Mythos 5.1.
On the Claude API, a request from an organization or workspace without 30-day retention returns a
400 invalidrequesterror .
Organizations with a ZDR arrangement should contact their Anthropic account team, or configure
retention for individual workspaces.
See Model-specific data retention requirements for per-platform details.
Priority Tier: Neither model is supported on Priority Tier .
Fast mode: Both models support fast mode in Messages API requests.
For each model's platforms, see Availability of fast mode .
Where the two models diverge: Availability: On the Claude API, Claude Fable 5.2 doesn't require
access approval.
Claude Mythos 5.2 is available only to organizations verified through Anthropic's verification
programs, such as the Cyber Verification Program .
To request access, apply to the program that covers your use case, or contact your Anthropic account
team.
Rate limits: Claude Fable 5.2 has its own rate limit, separate from the combined limit that Claude
Fable 5.1 and Claude Fable 5 share.
Claude Mythos 5.2 shares one combined limit with Claude Mythos 5.1 and Claude Mythos 5.
See Rate limits .
Migrating to Claude Fable 5.2 from Claude Fable 5.1 Migration is mostly drop-in.
The API surface, always-on adaptive thinking, the forced tool choice restriction, refusal handling,
stopdetails categories, and the data retention requirement all match Claude Fable 5.1.
Claude Fable 5.2 costs less: $8 USD per million input tokens and $40 USD per million output tokens,
compared with $10 USD and $50 USD on Claude Fable 5.1.

Breaking changes Failed prefix checks return a 400 error: On Claude Fable 5.2, each request gets a
prefix check .
A prefix check fails if you change system , tools , or earlier messages mid-conversation and then
send thinking blocks back.
If a prefix check fails, the request receives a 400 error.
Nothing changes for you if Claude Code, claude.ai, Claude Managed Agents , or the Claude Agent SDK
manages your conversation history.
If your code builds the messages array itself, compare what it does between requests with If your
code changes the system prompt, tools, or history .
If your code makes one of those changes between requests, the thinking that already follows the
change is invalid.
A later request that sends it back returns a 400 error: messages.5.content.0: Invalid signature in
thinking block.
The block is bound to a different conversation.
Remove the block, or set thinking.blockbinding.prefixmismatchbehavior to "dropblock".
That setting requires the thinking-binding-controls-2026-08-01 value in the anthropic-beta header.
 Retrying the same request body doesn't clear the error.
To find these edits before you switch production traffic, run the test in Test your code for prefix
check failures against the model you use now, Claude Fable 5.1 or Claude Opus 5.5.
If you use the MCP connector without pinning a server's tool list , also run the test against
claude-fable-5-2 .
For Claude Fable 5.2 thinking blocks, a tool list that changes between requests is an edit.
For Claude Fable 5.1 or Claude Opus 5.5 blocks, it isn't.
For the fix for each pattern, see Change tools or instructions without failing the prefix check .
In production, leave prefixmismatchbehavior at its default, "error" , if a mismatch can only mean a
bug in your code.
To drop the affected blocks and continue without that reasoning while you fix the edit, set it to
"dropblock" .
Treat that as a stopgap, not a long-term setting: dropping blocks can raise output tokens .
You can continue a Claude Fable 5.1 or Claude Opus 5.5 conversation on Claude Fable 5.2.
If you changed system , tools , or earlier messages in it, it can get the 400 error: see Thinking
block bound to a different conversation .
Claude Fable 5.1 can't read Claude Fable 5.2's thinking blocks: On the Claude API and Claude Models
on Google Cloud (Google managed), Claude Fable 5.2 reads Claude Fable 5.1's blocks, so a
conversation that moves from claude-fable-5-1 onto claude-fable-5-2 keeps its earlier reasoning.
In the other direction, Claude Fable 5.1 can't read Claude Fable 5.2's blocks.
If a router switch, a client-side retry, or a classifier refusal fallback moves a conversation from
Claude Fable 5.2 to another model, Claude Fable 5.1 included, the API drops the blocks that model
can't read.
The request succeeds, and you aren't billed for the dropped input tokens.
The model then works without that reasoning, which can raise cost and latency on the first turn
after the switch.
With the thinking-binding-controls-2026-08-01 beta header, inputtransformations lists each dropped
block with reason: "modelbindingmismatch" .
See Switch models and back .

Behavior changes Prompt lines that ask for less thinking don't stop the model from thinking at
medium effort and above: Claude Fable 5.1 usually follows a line such as "answer directly without
deliberating." In Anthropic's testing, such a line didn't stop Claude Fable 5.2 from thinking at
medium and above.
Remove these lines and lower the effort level.
See Calibrate effort .
The model can start subagents to review its own work at higher effort: In an agentic coding product
at higher effort levels, such as xhigh and max , Anthropic observed Claude Fable 5.2 using subagents
to review its own work.
Claude Fable 5.1 didn't do this on the same tasks.
Subagents can account for a large part of what a session costs.
See Set expectations for subagents .
A small maxtokens can leave no room for text: Thinking tokens count toward maxtokens , so a request
with a small maxtokens can stop with stopreason: "maxtokens" after a thinking block and before any
text.
A prompt line that usually keeps Claude Fable 5.1 from thinking doesn't keep Claude Fable 5.2 from
thinking at medium effort and above.
So a request that relied on such a line to fit a small maxtokens on Claude Fable 5.1 can run out of
tokens before any text on Claude Fable 5.2.
Raise maxtokens to leave room for thinking, or choose a lower effort level.
For the other behaviors to check when you carry prompts over, see Behavior differences .
